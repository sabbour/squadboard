# Changelog Authoring

**Category:** release

Keep a Changelog format: Added / Changed / Deprecated / Removed / Fixed / Security sections, user-facing language.

## Changelog Authoring

Follow [Keep a Changelog](https://keepachangelog.com) format:

```
## [x.y.z] — YYYY-MM-DD
### Added
- ...
### Changed
- ...
### Deprecated
- ...
### Removed
- ...
### Fixed
- ...
### Security
- ...
```

**Rules:**
- Write for users, not for developers. Describe impact, not implementation.
- Every public-facing change gets an entry. Internal refactors don't.
- Link to relevant issues / PRs with `([#123](url))`.
- Use present tense: "Adds support for X" not "Added support for X".
- Omit empty sections.
