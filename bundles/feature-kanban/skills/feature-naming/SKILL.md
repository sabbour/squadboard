## Naming checklist

- Names should describe user value or capability, not implementation.
- Prefer short, specific names over clever names.
- Avoid internal code names, roadmap labels, org names, and temporary project names.
- Check for confusing overlap with nearby features.
- Provide at least three options and one recommendation.

## Output

Return: recommended name, two alternates, rationale, rejected terms, and guidance for release notes or docs.
