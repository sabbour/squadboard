**Self-Fix:** Keyser immediately added visible feedback (button text change, opacity transition, background dim) + 3 component tests using vitest. Fix shipped as 57429237 same wave.

**Observation:** Regression was visual-only; backend dispatch was working throughout. Demonstrates importance of UI feedback testing for async operations. New vitest infrastructure in packages/client now provides coverage.

### 2. Verbal [910cb14c] → Suspected Root Cause of W27 Triad

**Issue:** W25 commit `2fc72086` (Verbal's sweep visualization work) introduced `sweep.tick` event emissions. This event has a different schema than `heartbeat.sweep.completed` (sweepName/status vs sweepId/outcome). When both land in the same server ring buffer, the client renders phantom "error / 1-4ms / unknown error" rows paired with real sweeps.

**Evidence:** Brady's W26 follow-up screenshot shows:
- Phantom no-name "error" row paired with every named sweep tick
- React duplicate-key warnings 397, 398, 399, 400+ (two events per tick, same seq)
- WebSocket connection fails (Vite dev proxy not forwarding ws:// upgrades)

**Routing:** Three distinct bugs now routed to Verbal for W27 priority. Likely root cause: `sweep.tick` schema mismatch in the same event buffer.

**Observation:** Schema consistency across event types is critical when multiple emitters write to the same observable. Verbal's W26 payload (pickup-todos sweep) will interact with these three bugs in W27.

## (e) Spawn Plain-Language Summaries

### Hockney W26 [c762610a]

> Charter parser was forwarding markdown bold syntax (`**Preferred:** auto`) to the platform API instead of extracting the sentinel value `auto`. The parser's `case 'model':` handler only stripped the leading bullet, leaving `**Preferred:** auto` intact. Root cause: missing markdown syntax unwrap in the regex. Fix: added pattern detection for `**Key:** value` (bold) and `Key: value` (plain text) with extraction of just the value portion. Also guards sentinel values `auto`, `default`, and empty strings — these now result in `undefined` model field, allowing the platform to select. Verified with 12 new regression tests in `charter-parser.test.ts`. All existing tests pass.

### Keyser W26 [53cba6eb]

> Four UI bugs in one batch: (1) RoutingLogTable crashes when server returns non-array or type-mismatched score, fixed with runtime type checks + ErrorBoundary; (2) Reassign and Run actions incorrectly open detail panel due to event bubbling, fixed by moving footer outside `onClick` wrapper and adding reassign agent-picker dropdown; (3) Dead "Investigate in Conjure" MenuItem removed from CardDetail header; (4) Heartbeat nav link breaks project scope by navigating to `/heartbeat` instead of `/projects/:id/heartbeat`, fixed to preserve scope context. All four fixes ship together in commit 53cba6eb. No regression tests added (pre-existing test infrastructure in packages/client is sparse).

### Keyser W26 Run-Click [57429237]

> Batch 1 (commit 53cba6eb) fixed the event bubbling that blocked Run button clicks from opening the detail panel. Unintended side-effect: users no longer received visual feedback that their click was received (the panel opening used to serve as confirmation, now gone with stopPropagation). New evidence from Brady: button looks identical while pending; users concluded "click did nothing." Fix: extended the `isPending` logic into the button's style (cursor + opacity) and text label (`▶ Run` → `Starting…` while pending). Added smooth transitions (150ms) for opacity and background color. Verified with 3 new component tests using vitest + @testing-library/react. All tests pass; build clean.

### Verbal W26 [910cb14c]

> Two intertwined bugs broke the "create issue → auto-run" end-to-end loop. Bug A: auto-assignment keyword router had a word-length filter of `> 3` chars, allowing generic 4-letter words like `"type"` and `"icon"` in Fenster's pattern to match almost any issue, routing unrelated work to Fenster instead of leaving it unassigned. Fix: raised threshold to `> 4` (5+ chars), removing spurious matches. Also deterministically ordered agent fallbacks (ORDER BY name) and removed arbitrary picks in MCP `run_agent`. Bug B: no sweep existed to pick up To Do items that arrived without a routing match, so they sat dormant. Fix: added new `pickupTodosSweep` (10s interval) that scans To Do items without active runs, applies Tier-2 keyword scoring, and falls back to least-loaded agent distribution. Verified with 10 new test cases (7 Bug A + 3 Bug B); all 434 server tests pass.
