### Root Cause Analysis

**Confirmed root cause:** `resolveAnchorIssue` in `ceremony-scheduler.ts` (line 131) picks most recently created issue:

```ts
.orderBy(sql`${schema.issues.createdAt} DESC`)
.limit(1);
```

- Fan-out child issues (`Foo — verbal`, `Foo — fenster`) are most recently created after fan-out
- On next cron tick, scheduler anchors new workflow run on most-recent child (e.g., `Foo — fenster`)
- That child has a fan-out step in workflow YAML → creates grandchildren (`Foo — fenster — verbal`, etc.)
- Pattern `Foo — verbal — verbal — fenster` is slice of ever-deepening tree

**Secondary compounding vector:** `UPDATE step_runs SET status = 'splitting'` in `materializeFanOut` had no `AND status = 'pending'` guard; two concurrent `advanceWorkflowRun` calls both pass check → both create child issues.
