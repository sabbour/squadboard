## Decisions

### 1. Resume buffer size: **100 events**

Chosen to cover realistic reconnect windows (a burst of 100 delta tokens takes ~10–30 s to stream). Older events are evicted with a simple `buf.shift()`. Memory cost is O(active_sessions × 100 × avg_payload_size) — negligible.

### 2. WS → SSE fallback timeout: **3 s**

Matches spec verbatim. Implemented via `setTimeout(3_000)` in `useConsultStream`. The WS singleton's `onStateChange` listener handles mid-stream disconnect → SSE switch independently (no timeout needed for that path).

### 3. SSE event format

Each event uses the full `ConsultEventType` string as the SSE `event:` field (e.g. `event: consult.message_delta`). This lets the browser EventSource API route events to the correct `addEventListener` handler without custom parsing.

### 4. Heartbeat shapes

- **WS:** `ws.ping()` native frame every 15 s per-connection; `ws.terminate()` on missing pong (next 15 s tick). Exposed `WS_PING_INTERVAL_MS = 15_000` constant for testability.
- **SSE:** `:heartbeat\n\n` comment line every 15 s; `setInterval` is cleared on `res.on('close', ...)`.

### 5. SSE terminal events

`consult.completed` and `consult.error` close the SSE stream server-side (`res.end()`). No keep-alive after session ends.

### 6. WS resubscribe protocol

New client→server message type `resubscribe` with `{ projectId, lastSeq }`. Server calls `getBufferedEvents(sessionId, lastSeq)` from `sdk/sse-stream.ts` (shared buffer) and replays via normal WS `send`. Only applicable to `consult:*` rooms.

### 7. Client transport tracking

`activeTransportRef` (ref, not state) is used to gate handlers without triggering extra re-renders. `transport` state (ws/sse/null) is exported for UI status indicators.

### 8. Retry bar

Two consecutive SSE `onerror` callbacks → `showRetryBar = true`. The Retry button calls `window.location.reload()` — simplest reliable way to reset all transport state cleanly.

### 9. Backward compatibility

`useConsultStream` now returns `{ entries, transport, showRetryBar }` instead of a bare array. Both `Consult.tsx` and `ContextPanel.tsx` are updated. A `useConsultStreamEntries()` shim is exported for any future callers that only need the array.

### 10. SSE route placement

`GET /:sessionId/stream` is added at the end of `consultRouter` (after all specific `:sessionId` subroutes) to avoid shadowing `/:sessionId/proposals`, `/:sessionId/messages`, etc. Express matches in registration order.
